# Earth Migration 手机轻量模式设计

日期：2026-10-11

## 背景与问题

GitHub Pages 公网页面在微信内置浏览器中停留于 `CALIBRATING DEEP-SPACE OPTICS`。该阶段当前会并行下载并解码多张 4K 地球与银河贴图、星表和两个 GLB 模型。虽然代码已为触屏设备选择 `low` 画质档，但低画质档只降低渲染实例与帧率，没有减少首批资源，因此移动端仍可能因网络、解码时间或显存压力无法完成启动。

## 目标

- 手机和微信内置浏览器自动进入轻量模式，无需用户选择。
- 首屏先加载必要资源并尽快显示可操作的开始界面。
- 桌面端保持当前高清资源和视觉效果。
- 手机端仍保留完整的地球、太阳系与银河尺度体验，允许远景资源在后台补齐。
- 加载失败时显示明确的重试和外部浏览器提示，不再永久停在加载画面。

## 非目标

- 不重做现有界面、故事、镜头或交互逻辑。
- 不改变桌面端的资源质量与默认画质档。
- 不新增后台服务、数据库或用户账户。
- 不保证所有低端设备达到固定帧率，但必须避免因首批资源过重而无法进入。

## 总体方案

采用“移动端轻量资源 + 两阶段加载”的组合方案。

### 设备与模式选择

沿用现有 `TOUCH`、视口尺寸和 `MOBILE` 判断。手机默认使用 `mobile-lite` 资源配置；查询参数可保留调试覆盖能力。桌面仍使用现有高清配置。

### 第一阶段：可进入的核心场景

手机首批只加载：

- 经过缩小的地球日景、夜景、表面和云层贴图；
- 经过缩小的银河背景；
- 星表的移动端裁剪版本或受控抽样；
- 进入标题页和地球近景所必需的脚本与几何。

首批不阻塞于 ISS、哈勃模型、PBR 材质集、全部行星高清贴图和银河俯视纹理。核心场景构建完成后关闭加载页，允许用户开始影片或自由探索。

### 第二阶段：后台补齐

开始界面出现后，浏览器空闲时按使用概率加载：

1. 太阳系行星的移动端纹理；
2. 银河俯视纹理与远景数据；
3. ISS、哈勃模型和 PBR 材质。

未完成加载时，相关对象使用颜色材质、程序化材质或已有轻量纹理作为占位。资源完成后无刷新替换，失败则继续使用占位，不阻断主体验。

### 移动端渲染预算

在现有 `low` 档基础上进一步限制：

- 渲染像素比和总像素预算；
- MSAA、阴影、Bloom 层数和体积光步数；
- 银河星点、局部旋臂、尘埃、引擎和小天体实例数量；
- 首屏关闭非必要模型和 PBR 材质。

这些限制只应用于 `mobile-lite`，桌面档不变。

## 资源产物

从现有源图生成移动端专用资源，保留原文件：

- 地球与银河关键贴图：最长边约 1024–2048 像素；
- 行星贴图：最长边约 512–1024 像素；
- 星表：确定性抽样，确保每次构建内容一致；
- 保持与原资源相同的色彩空间和用途，不用有损压缩破坏法线或数据贴图。

资源使用独立路径或明确后缀，避免桌面端误加载轻量版本。

## 加载状态与错误处理

- 加载状态显示真实阶段，不把后台资源计入阻塞首屏的进度。
- 核心资源超时或 WebGL 初始化失败时，加载层显示中文可执行提示。
- 提供“重新加载”和“在系统浏览器打开”的操作；后者在微信环境中给出复制链接提示作为回退。
- 监听 `webglcontextlost`，停止渲染并显示恢复建议，避免黑屏或假死。
- 后台资源失败只记录并保留占位，不触发全局 `SYSTEM FAULT`。

## 数据流与模块边界

- `main.js` 负责设备判断、阶段编排和加载状态。
- 新的资源清单模块只描述桌面与移动资源 URL、是否阻塞首屏及降级策略。
- `earth.js`、`solar.js`、`galaxy.js` 继续负责场景构建，通过可空资源或替换接口接收延迟资源。
- 生成脚本只负责从现有资源产生确定性的移动资源，不参与运行时逻辑。

## 验证方案

### 自动检查

- 所有模块通过语法检查。
- 移动资源均存在，尺寸和文件体积符合预算。
- 桌面资源 URL 与现有版本一致。
- GitHub Pages 上的 HTML、核心脚本、移动贴图和模型请求返回成功。

### 浏览器检查

- 微信内置浏览器或等效移动视口能越过 `CALIBRATING DEEP-SPACE OPTICS` 并显示开始界面。
- 低端模式下可开始影片、进入自由探索并切换到太阳系与银河尺度。
- 后台资源较慢或失败时页面仍可操作。
- 桌面端与修改前的入口、画质和交互一致。

## 完成标准

- 手机端不再无限停留在首个加载阶段。
- 移动端阻塞首屏的资源传输量不超过 8 MB，核心纹理解码后的理论 GPU 占用不超过 48 MiB。
- 核心加载超过 30 秒时进入可重试的错误状态，而不是继续无限等待。
- 核心加载失败能被用户看见并重试。
- 同一个 GitHub Pages 链接发布新版本，无需用户更换分享地址。
